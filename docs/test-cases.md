## 공통 조건과 상태 표기

- 대상 서비스: 네이버 데스크톱 웹 (`https://www.naver.com/`)
- 현재 실행 설정: Chromium, headed (`headless=False`), Viewport 1920×1080, 로케일 `ko-KR`, 타임존 `Asia/Seoul`
- 인터넷 연결 및 대상 서비스 접속이 가능한 환경을 전제로 합니다.
- 로그인 관련 TC는 로그아웃 상태를 전제로 하며, 실제 사용자 계정을 사용하지 않습니다.
- `scope="function"` fixture가 실행되는 각 테스트마다 브라우저·Context·Page를 새로 만들고 종료 시 정리합니다. Skip된 TC의 테스트 본문은 실행하지 않습니다.
- **구현:** 테스트 코드가 있으며 일반 실행 대상에 포함됩니다. 통과를 뜻하지 않습니다.
- **구현·Skip:** 테스트 코드는 있으나 Skip 설정으로 일반 실행에서 제외됩니다.
- 아래 상태는 구현과 실행 제외 여부를 뜻합니다. README에 기록된 `9 PASS · 0 FAIL · 1 SKIP (40.08초)`는 별도의 로컬 실행 기록이며, 이 문서를 작성하면서 다시 실행한 결과가 아닙니다. 새로운 실행 결과는 실행일·환경·대상 커밋과 함께 기록합니다.

- **입력 데이터:** 없음.
- **수행 절차:**
  1. 네이버 메인 페이지에 접속합니다.
  2. 메인 로그인 버튼의 표시 여부를 확인합니다.
- **기대 결과:** 메인 로그인 버튼이 표시됩니다.
- **코드:** [`tests/test_login.py`](../tests/test_login.py)의 `test_main_login_button_visible`
- **구현 상태:** 구현.

### C10003

**검증 목적:** 예시 아이디와 비밀번호가 각 입력 필드에 반영되는지 확인합니다.

- **사전 조건:** 공통 조건을 충족하고 로그아웃 상태입니다.
- **입력 데이터:** 아이디 `test_user`, 비밀번호 `test_pw`.
- **수행 절차:**
  1. 네이버 메인 페이지에서 로그인 화면으로 이동합니다.
  2. 아이디에 `test_user`, 비밀번호에 `test_pw`를 입력합니다.
  3. 각 입력 필드의 값을 확인합니다.
- **기대 결과:** 아이디 필드 값은 `test_user`, 비밀번호 필드 값은 `test_pw`와 일치합니다.
- **코드:** [`tests/test_login.py`](../tests/test_login.py)의 `test_naver_login_credentials_input`
- **구현 상태:** 구현.
- **검증 범위:** 예시 문자열의 입력값만 확인합니다. 로그인 버튼을 클릭하거나 로그인 성공을 확인하지 않습니다.

### C10004

**검증 목적:** 잘못된 아이디와 비밀번호를 제출했을 때 로그인 오류가 표시되는지 확인합니다.

- **사전 조건:** 공통 조건을 충족하고 로그아웃 상태이며, CAPTCHA 없이 오류 응답을 확인할 수 있어야 합니다. 현재는 이 조건을 안정적으로 충족할 수 없어 실행에서 제외합니다.
- **입력 데이터:** 아이디 `wrong_user`, 비밀번호 `wrong_pw`.
- **수행 절차:** 아래는 코드에 정의된 절차이며, 현재 일반 실행에서는 수행되지 않습니다.
  1. 네이버 메인 페이지에서 로그인 화면으로 이동합니다.
  2. 잘못된 아이디와 비밀번호를 입력합니다.
  3. 로그인 버튼을 클릭합니다.
  4. 로그인 오류 영역의 표시 여부를 확인합니다.
- **기대 결과:** `role="alert"`, `data-case="메시지 == 비밀번호오류메시지"` 조건에 해당하는 오류 영역이 표시됩니다. 오류 문구 전체의 일치 여부는 검증하지 않습니다.
- **코드:** [`tests/test_login.py`](../tests/test_login.py)의 `test_naver_login_invalid_credentials`
- **구현 상태:** 구현·Skip.
- **제외 사유:** `실제 네이버 인증 요청 시 CAPTCHA가 나타나 자동 검증에서 제외`
- **재검토 기준:** 인증 오류 응답을 안정적으로 확인할 수 있는 테스트 환경을 확보한 뒤, 기대 결과를 재확인하고 실행 재개를 검토합니다.

### C10005

**검증 목적:** 아이디와 비밀번호를 입력하지 않고 로그인 버튼을 클릭하면 아이디 입력 요청이 표시되는지 확인합니다.

- **사전 조건:** 공통 조건을 충족하고 로그아웃 상태입니다.
- **입력 데이터:** 아이디 `""`, 비밀번호 `""` (빈 문자열).
- **수행 절차:**
  1. 네이버 메인 페이지에서 로그인 화면으로 이동합니다.
  2. 아이디와 비밀번호 입력 필드를 비웁니다.
  3. 로그인 버튼을 클릭합니다.
  4. 아이디 입력 요청 메시지의 표시 여부를 확인합니다.
- **기대 결과:** `아이디 또는 전화번호를 입력해 주세요.` 메시지가 표시됩니다.
- **코드:** [`tests/test_login.py`](../tests/test_login.py)의 `test_naver_login_empty_credentials`
- **구현 상태:** 구현.
- **검증 범위:** 버튼 비활성화 여부나 비밀번호 단독 미입력 조건은 검증하지 않습니다.

## 검색

### C20001

- **사전 조건:** 공통 조건을 충족합니다.
- **입력 데이터:** 없음.
- **수행 절차:**
  1. 네이버 메인 페이지에 접속합니다.
  2. `#query` Locator로 검색 입력창의 표시 여부를 확인합니다.
- **기대 결과:** 검색 입력창이 표시됩니다.
- **코드:** [`tests/test_search.py`](../tests/test_search.py)의 `test_search_input_visible`
- **구현 상태:** 구현.
- **검증 범위:** 검색 입력창만 확인합니다. 검색 버튼의 표시나 클릭은 검증하지 않습니다.

### C20002

**검증 목적:** 키워드를 검색하면 검색 결과 페이지로 이동하는지 확인합니다.

- **사전 조건:** 공통 조건을 충족합니다.
- **입력 데이터:** 검색어 `테스트` (`SEARCH_KEYWORD`).
- **수행 절차:**
  1. 네이버 메인 페이지에 접속합니다.
  2. 검색창에 `테스트`를 입력합니다.
  3. 검색 입력창에서 `Enter` 키를 누릅니다.
  4. `wait_for_url("https://search.naver.com/**", wait_until="domcontentloaded", timeout=10000)`로 검색 결과 URL과 페이지 로드를 기다립니다.
  5. 현재 페이지 URL을 확인합니다.
- **기대 결과:** 현재 URL이 `https://search.naver.com/`로 시작합니다.
- **코드:** [`tests/test_search.py`](../tests/test_search.py)의 `test_search_functionality_redirect`
- **구현 상태:** 구현.
- **검증 범위:** 검색 후 URL의 접두사 일치 여부를 검증합니다. 입력한 검색어가 URL이나 결과 화면에 반영되는지, 결과 목록의 내용·정확성, 결과 건수는 검증하지 않습니다.

## 변경 시 확인할 내용

1. 검증 절차나 Assertion이 바뀌면 해당 TC의 절차·기대 결과·검증 범위도 수정합니다.
2. TC를 추가하거나 삭제하면 목록과 README의 영역별 개수를 함께 수정합니다.
3. 함수명이나 파일 경로가 바뀌면 문서의 코드 연결을 함께 수정합니다.
4. Skip 설정을 바꾸면 구현 상태, 제외 사유, README의 실행 대상 개수를 함께 수정합니다.
5. PASS·FAIL·SKIP 실행 결과는 코드 정의 개수와 구분하여 기록합니다.
